System Information

Audience: End users, system administrators Last Updated: 2026-04-05 Version: 2.0.0

Overview​

The System Information module manages the connection between Llamafin and your Jellyfin server, monitors app activity state, and handles platform-specific optimizations like battery management on Android devices.

Think of it as the app's "nervous system" — it knows which server you're connected to, whether the app is visible on screen or running in the background, and how to keep the music playing efficiently on your device.

What It Does​

  • Manages Server Connections: Tracks which Jellyfin server you're connected to and tests new connections
  • Monitors App State: Knows when the app is in the foreground vs. background
  • Measures Server Latency: Tests how quickly your server responds
  • Handles Battery optimisation: On Android, manages battery exemption settings for background playback
  • Migrates Legacy Configurations: Automatically upgrades from older app versions
  • Schedules Re-engagement Reminders: Optional notifications to remind you to return to the app
  • Controls Server Lifecycle: Can restart or shut down the Jellyfin server remotely

Key Concepts​

Server URL Management​

The app tracks which Jellyfin server you're connected to. This URL is the foundation for all communication — every API call, image load, audio stream, and WebSocket connection depends on having the correct server address.

ConceptDescription
Active Server URLThe address of the Jellyfin server you're currently connected to
Public System InfoBasic server identity (name, version) available without logging in
System InfoDetailed server information available after authentication
Server PingHow long it takes the server to respond, measured in milliseconds

Connection Testing​

When you add a new server, the app tests the connection intelligently:

ScenarioBehaviour
IP address enteredTries HTTP first, then HTTPS as fallback
Domain name enteredTries HTTPS first, then HTTP as fallback
Network unreachableReports connection failure
Server not found (404)Reports server not found
Invalid URL formatReports invalid URL before attempting connection

App State Tracking​

The app knows whether it's visible on screen or running in the background:

StateDescriptionBehaviour
Active (Foreground)App is visible on screenFull functionality, visualizers enabled
Inactive (Background)App is minimised but runningVisualizers disabled to save resources, re-engagement timer starts

Battery optimisation (Android Only)​

On Android, the system may restrict background app activity to save battery. Llamafin can request an exemption to ensure uninterrupted playback.

StatusDescription
UnknownBattery optimisation status hasn't been checked yet
RestrictedAndroid may limit background activity (music may stop)
UnrestrictedAndroid will not limit background activity (recommended)

Configuration​

Server Management​

Servers are managed through Settings → Source (not directly in System Information). The System module automatically tracks whichever server is marked as "active."

ActionWhere to Configure
Add a new serverSettings → Source → Add Server
Switch serversSettings → Source → Select server
Remove a serverSettings → Source → Delete server
Test connectionLogin page or Add Server modal

Server Ping​

You can test the latency of your active server to check connection quality:

MetricDescription
PingRound-trip time to the server in milliseconds
GoodUnder 50ms — responsive playback
Acceptable50-200ms — minor delay possible
PoorOver 200ms — noticeable lag, buffering likely

Battery optimisation​

Battery optimisation settings are found at Settings → Advanced → Remote Control:

SettingDescriptionDefault
Keep App AliveRequests battery exemption so the app can run in the backgroundDisabled

When enabled on Android:

  1. The app checks if it has battery exemption
  2. If restricted, it offers to open the system settings screen where you can grant exemption
  3. The check runs automatically when:
    • You enable "Keep App Alive"
    • You return to the app from the background
    • A car display connects (Android Auto)

Re-engagement Reminders​

Optional notifications that remind you to return to the app after it's been in the background:

SettingWhereDefault
Re-engagement RemindersSettings → NotificationsDisabled

When enabled:

  • If the app goes to the background, a notification is scheduled for 3 days later
  • If you return to the app before then, the notification is cancelled
  • Tapping the notification opens the app directly to the home screen

How It Works​

Server URL Lifecycle​

App First Launch
    │
    ├── No server configured
    │     └── Shows login screen
    │
    ├── User adds a server
    │     └── Connection tested automatically
    │           │
    │           ├── Success → Server saved and activated
    │           └── Failure → Error message with details
    │
    └── Server URL stored for all future API calls

Switching Servers
    │
    ├── User selects a different server in Settings
    │     │
    │     ├── Old server data cleared
    │     ├── New server URL activated
    │     └── All features reconnected to new server
    │
    └── If all servers are removed
          └── App returns to "no server" state

Removing Last Server
    │
    ├── Server removed from list
    ├── Server URL cleared
    └── Any open settings dialogues closed automatically

Connection Testing Flow​

When you test a new server connection:

User enters server address
    │
    ├── App determines protocol based on address type:
    │     │
    │     ├── IP address (e.g., 192.168.1.100) → Try HTTP first
    │     └── Domain name (e.g., jellyfin.example.com) → Try HTTPS first
    │
    ├── Attempts connection to primary URL
    │     │
    │     ├── Success → Server added and activated
    │     │
    │     └── Network failure (unreachable, timeout, CORS)
    │           │
    │           └── Try fallback protocol
    │                 │
    │                 ├── Success → Server added and activated
    │                 └── Failure → Connection error reported
    │
    └── Non-network errors (404, 401, invalid URL)
          └── Fail immediately (no fallback)

Battery optimisation Flow (Android)​

Trigger (any of 3 events):
  1. User enables "Keep App Alive" setting
  2. User returns to app from background
  3. Android Auto connects
          │
          └── Check: Is this Android?
                │
                ├── No → Do nothing
                │
                Yes
                │
                └── Check: "Keep App Alive" enabled OR car connected?
                      │
                      ├── No → Do nothing
                      │
                      Yes
                      │
                      └── Query battery optimisation status
                            │
                            ├── Unrestricted → All good, no action needed
                            │
                            └── Restricted → Show option to open settings
                                  │
                                  └── User can grant exemption in Android settings

App State Transitions​

App Launch
    │
    └── State: ACTIVE (foreground)
          │
          ├── User presses Home button
          │     │
          │     └── State: INACTIVE (background)
          │           │
          │           ├── Re-engagement timer starts (3 days)
          │           ├── Visualizers disabled
          │           └── Background playback continues
          │
          └── User returns to app
                │
                └── State: ACTIVE (foreground)
                      │
                      ├── Re-engagement timer cancelled
                      └── Visualizers re-enabled

Legacy URL Migration​

For users upgrading from older versions of the app:

App detects no configured server
    │
    └── Checks for legacy "jellyfin_url" in old storage
          │
          ├── Found → Navigate to login with pre-filled URL
          │           │
          │           └── User can confirm or change the URL
          │
          └── Not found → Show empty server list

Integration with Other Features​

The System Information feature is one of the most depended-upon modules in the entire app. Here's how it connects to other parts of Llamafin:

Authentication​

The server URL is required for all login attempts. When you authenticate, the app sends credentials to the active server URL.

Audio Playback​

Audio streaming, artwork loading, and EQ settings all depend on the server URL to construct the correct resource URLs.

Media Session API​

Over 18 playback commands (play, pause, skip, seek, volume) use the server URL to communicate with Jellyfin.

WebSocket Connection​

Real-time events (playback state changes, library updates) require a WebSocket connection to the server.

Image Loading​

All album art, artist photos, and backdrops are loaded from URLs derived from the active server address.

Library Operations​

Browsing albums, artists, songs, and playlists all require the server URL for API calls.

Network Management​

Network connectivity checks and speed tests use the server URL as the test endpoint.

Error Handling & Reliability​

Self-Healing Mechanisms​

ScenarioBehaviour
Server URL changesAll cached server data (info, ping) is cleared to prevent showing stale information
All servers removedApp resets to "no server" state and closes any open settings dialogues
Legacy configuration foundUser is guided through migration to the new server management system
Connection test failsDetailed error message provided (invalid URL, connection blocked, server not found)
Battery optimisation check failsSilently handled — no error shown to user

Error Classifications​

When testing a server connection, errors are classified as:

Error TypeMessageCause
Invalid URL Format"Invalid URL Format"Malformed address (not a valid URL)
Mixed Content or CORS Block"Mixed Content or CORS Block"Network-level issue (wrong protocol, firewall, unreachable)
Server ErrorServer's error messageServer responded with an error (404, 500, etc.)

Known Limitations​

LimitationImpact
No automatic re-pingServer latency is only measured manually — no periodic health check
No automatic reconnectionIf the server goes down, the app doesn't automatically try to reconnect
Battery optimisation limited to AndroidiOS manages background apps differently — no equivalent setting
Re-engagement notifications are basicFixed 3-day delay with no customisation options

Server Management Quick Reference​

Adding a Server​

  1. Go to Settings → Source
  2. Tap Add Server
  3. Enter the server address (IP or domain)
  4. Tap Test Connection
  5. If successful, the server is saved and activated

Switching Servers​

  1. Go to Settings → Source
  2. Select the server you want to use
  3. The app automatically reconnects to the new server

Removing a Server​

  1. Go to Settings → Source
  2. Swipe or tap delete on the server
  3. Confirm the deletion
  4. If it was the last server, the app returns to "no server" state

Testing Server Latency​

  1. Go to Settings → Advanced → System
  2. Tap Ping Server
  3. The latency (in milliseconds) is displayed
